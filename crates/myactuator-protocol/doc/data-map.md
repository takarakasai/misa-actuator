# MyActuator RMD CAN V3 — 設定・取得データ一覧

出典: `ref/RMD-X-Servo-Motor-Control-Protocol-V3.91.pdf`（V3.9 マニュアル）。
「実装」列は misa-actuator の `myactuator-protocol` / `myactuator-driver` での対応状況（2026-07-20 時点）。

> 2026-07-26: X4-36 向けに `ref/X4-36_Motor_Motion_Protocol.pdf`（V4.3）を追加取得し突き合わせ済み。
> 本 crate が対応するコマンド範囲では V3.9→V4.3 の仕様差分なし（詳細は
> [`x4-36-v4.3-analysis.md`](x4-36-v4.3-analysis.md)）。ただし同時に、モーションモード応答の
> デコードバグ（1バイトオフセット誤り）を発見・修正した。詳細は同ファイル参照。
>
> 2026-07-26: 0x30（PID 読み）/0x42（加速度読み）を実装・実機（X4-36, can1, id 1）で検証。
> 併せて `myactuator-cli params` を追加：既知の読み取り可能パラメータ（0x9A/0x9C/0x92/0x30/0x42×4/0xB2/0xB5）を
> 一括取得しコンソール表示、`--toml` / `--out <path>` で TOML ダンプにも対応。個々のコマンドが
> タイムアウト/未対応でも他の項目には影響しない（該当項目のみ欠落として表示・シリアライズから省略）。
>
> 2026-07-26（続報）: `params` で取得できる項目が RobStride 側と比べて少ないという指摘を受け、
> `ref/` 以下の V3.9 / X4-36 V4.3 / X-series の3マニュアルを突き合わせてギャップ分析を実施。
> **重大な発見**: 0x30（PID読み）は V4.2（2024.5.28）以降 `index + Float` 方式に変更されており、
> 旧実装（6 個の uint8 を一括返却する V3.9 の古い方式）は実機 X4-36（FW 2026-04-24）とは
> 一致していなかった。旧実装が実機で「全ゲイン 0」を返していたのはこのフォーマット不一致が原因
> （index 未指定＝0 として解釈され、無効な index に対する float 0.0 が返っていた）。
> `0x30`/`0x31`/`0x32` を V4.2+ の `index+Float` 方式に修正し、実機で実際の非ゼロゲイン値
> （例: current_kp=1.5, position_kd=0.5）を確認した。
> 併せて 0x60/0x61/0x62（多回転エンコーダ）・0x70（運転モード）・0x71（モータ電力）・
> 0x90（単回転エンコーダ）・0x94（単回転角）・0x9D（Status3 相電流）・0xB1（稼働時間）を新規実装、
> `0x9A` に MOS 温度フィールド（X4-36 V4.3 で追加）、`ErrorState` に 2 ビット
> （0x0800 部品過熱, 0x4000 エンコーダデータエラー）を追加。`params` は現在 20 種類超の値を返す。
> 実機検証で判明した個体差: **0x71 と 0x90 はこの X4-36（ギア付きモデル）ではタイムアウトし
> 未実装**（0x71 は X4-36 V4.3 マニュアル自体に節がなく V3.9 のみの記載、0x90 は
> "direct-drive モデル用" と明記されダイレクトドライブでない本機では非対応と推測）。
> **0x94（単回転角）はタイムアウトせず応答するが値は `0xFFFF`（655.35°、有効範囲 0–359.99° 外）
> — この機種では意味を持たないセンチネル値と判断**。0x79（CANID 読み）は特殊なブロードキャスト
> アドレス `0x300` 宛送信が必要（既存の `0x140+ID` per-motor 経路と異なる）で、過去の
> RobStride SET_CAN_ID インシデント（`[[robstride-param-table-design]]`）の教訓から、
> 読み取り専用であっても意図的に未実装のまま据え置いた（将来の検討課題）。

単発コマンドは `0x140+ID` に送信し `0x240+ID` で応答（`data[0]` がコマンドバイトをエコー）。
モーションモードのみ `0x400+ID` → `0x500+ID`。

## 1. 取得（読み取り専用）

| cmd | 内容 | データ型 / 単位 | 実装 |
|-----|------|----------------|------|
| 0x30 | PID パラメータ読み（index で電流/速度/位置ループの各 KP/KI/KD を1つずつ指定, V4.2+方式） | Float（生ゲイン値）。index: 0x01 電流KP, 0x02 電流KI, 0x04 速度KP, 0x05 速度KI, 0x07 位置KP, 0x08 位置KI, 0x09 位置KD | ✅ `read_pid_gain(index)` / `read_pid()`（7回読み一括, 実機で非ゼロ値確認済み） |
| 0x42 | 加速度読み（index で位置/速度計画の加減速を選択） | int32, 1 dps/s（範囲 100–60000, X4-36 V4.3 マニュアル準拠） | ✅ `read_acceleration`（実機 X4-36 で4種とも 5000 dps/s を確認。応答 `data[1]` は実機ではリクエストの index を正しくエコーするが、マニュアル例は常に 0x00 — 未検証扱い） |
| 0x60 | 多回転エンコーダ位置（ゼロオフセット適用後） | int32, pulses | ✅ `read_multi_turn_encoder` |
| 0x61 | 多回転エンコーダ原始位置（オフセット適用前） | int32, pulses | ✅ `read_multi_turn_encoder_raw` |
| 0x62 | 多回転エンコーダゼロオフセット | int32, pulses | ✅ `read_multi_turn_zero_offset` |
| 0x90 | 単回転エンコーダ値（ダイレクトドライブ機用） | uint16 ×3（encoder/raw/offset） | ✅ `read_single_turn_encoder`（実機 X4-36〔ギア付き〕ではタイムアウト — 非対応の可能性） |
| 0x92 | 多回転絶対角 | int32, 0.01 °/LSB | ✅ driver `read_multi_turn_centideg` |
| 0x94 | 単回転角 | 0.01 °/LSB（マニュアルは範囲 0–35999 と明記するが型は矛盾する `int16_t` — 本実装は範囲優先で `u16` 採用） | ✅ `read_single_turn_angle`（実機 X4-36 では `0xFFFF`=655.35° を返す — 有効範囲外の値でこの機種では無意味と判断） |
| 0x9A | Status1: 温度 / MOS温度 / ブレーキ状態 / 母線電圧 / エラーフラグ | int8 ℃, int8 ℃(X4-36 V4.3 で追加), bool, uint16 0.1 V, uint16 ビット列 | ✅ `read_status`/`read_status1` |
| 0x9C | Status2: 温度 / iq / 出力軸速度 / 出力軸角 | int8 ℃, int16 0.01 A, int16 1 dps, int16 1 ° | ✅ `read_status2` / `measure` |
| 0x9D | Status3: 温度 / A・B・C 相電流 | int8 ℃, int16 ×3, 0.01 A | ✅ `read_status3` |
| 0x70 | 現在の運転モード（1=電流 2=速度 3=位置ループ） | uint8 | ✅ `read_run_mode` |
| 0x71 | モータ電力 | uint16, 0.1 W | ✅ `read_motor_power`（実機 X4-36 ではタイムアウト — X4-36 V4.3 マニュアルに節自体が存在せず、この世代のFWでは未実装と推測） |
| 0xB1 | システム稼働時間 | uint32, ms | ✅ `read_uptime_ms` |
| 0xB2 | ソフトウェアバージョン日付 | uint32（例 20211126） | ✅ `read_version_date` |
| 0xB5 | モータ型番文字列 | ASCII | ✅ `read_motor_model`（実機 X4-36 では空文字列を確認） |
| 0x79 (flag=1) | CANID 読み | uint16 (1–32) | 未実装（意図的）。特殊アドレス `0x300` へのブロードキャスト送信が必要で、通常の per-motor 経路と異なるため — [[robstride-param-table-design]] の SET_CAN_ID インシデントの教訓から、読み取り専用でも今回のスコープでは見送り |

エラーフラグ（0x9A）: 0x0002 ストール / 0x0004 低電圧 / 0x0008 過電圧 / 0x0010 過電流 /
0x0040 パワー超過 / 0x0080 校正書込エラー / 0x0100 過速度 / 0x0800 部品過熱(X4-36 V4.3 追加) /
0x1000 モータ過熱 / 0x2000 エンコーダ校正エラー / 0x4000 エンコーダデータエラー(X4-36 V4.3 追加)。

## 2. 設定（書き込み） — 保存先: 揮発(RAM) / 不揮発(ROM・FLASH)

| cmd | 内容 | 保存先 | 反映タイミング | 実装 |
|-----|------|--------|----------------|------|
| 0x31 | PID → RAM 書き（0x30 と同じ index+Float 方式, V4.2+） | **揮発**（電源断で消える） | 即時 | — |
| 0x32 | PID → ROM 書き（0x30 と同じ index+Float 方式, V4.2+） | **不揮発** | 即時 | — |
| 0x43 | 加速度書き（index 0x00 位置計画加速 / 0x01 位置計画減速 / 0x02 速度計画加速 / 0x03 速度計画減速） | **RAM+ROM 同時 = 不揮発**（RAM だけに書く選択肢なし） | 即時 | — |
| 0x63 | 指定した多回転値を ROM にゼロとして書き | **不揮発** | **要再起動** | — |
| 0x64 | 現在位置を ROM にゼロとして書き | **不揮発**（フラッシュ摩耗注意） | **要再起動** | ✅ `set_zero_rom` |
| 0x20 idx 0x01 | 多回転値クリア（ゼロ更新して保存） | **不揮発** | **要再起動** | ✅ `function_control` 経由 |
| 0x20 idx 0x02 | CANID フィルタ有効/無効（0x280 マルチモータ指令使用時は無効化が必要） | **不揮発**（FLASH 保存と明記） | 即時 | ✅ `function_control` 経由 |
| 0x79 (flag=0) | CANID 設定（1–32） | 明記なし（実質不揮発の想定。実機で要確認） | — | — |
| 0xB3 | 通信断保護時間（ms、0=無効。超過で出力遮断+ブレーキロック） | 明記なし（実機で要確認） | 即時 | — |
| 0xB4 | 通信ボーレート（CAN: 0=500K, 1=1M / RS485: 0=115200 … 4=2.5M） | **不揮発**（ROM 保存と明記） | **次回電源投入時** | — |
| 0xB6 | アクティブリプライ設定（0x60/61/62/92/9A/9C/9D/9E を周期自動送信、周期 10 ms 単位。CAN 版のみ） | 明記なし（運転時機能 = 揮発想定） | 即時 | — |

## 3. 運転指令（状態のみ変化 = すべて揮発）

| cmd | 内容 | 実装 |
|-----|------|------|
| 0xA1 | トルク（iq 電流）閉ループ, int16 0.01 A/LSB。**ラッチする**（次の指令まで維持） | ✅ `set_torque` / `set_current` |
| 0xA2 | 速度閉ループ, int32 0.01 dps/LSB（出力軸） | ✅ `set_velocity` |
| 0xA4 | 多回転絶対位置閉ループ + maxSpeed (uint16 1 dps) | ✅ `set_position` |
| 0xA6 | 単回転位置閉ループ（回転方向指定付き） | — |
| 0xA8 | 増分位置閉ループ | — |
| 0xA9 | 強制トルク制限付き位置閉ループ（X4-36 V4.3 で新規追加, maxTorque指定） | — |
| 0x400+ID | モーションモード (MIT): p±12.5 rad / v±45 rad/s / kp 0–500 / kd 0–5 / t±24 N·m（RMD-X V3 ファーム限定） | ✅ `motion_control` |
| 0x80 | シャットダウン（出力 OFF・運転状態クリア） | ✅ `shutdown` |
| 0x81 | 停止（閉ループ維持のまま停止） | ✅ `stop` |
| 0x76 | システムリセット（再起動。ROM ゼロ書き反映に必要） | ✅ `system_reset` |
| 0x77 / 0x78 | ブレーキ解放 / ロック（ブレーキ付きモデル） | ✅ `brake_release` / `brake_lock` |

## 4. 補足

- ドライバの `rezero()`（ソフトゼロ）はモータ側に何も書かない（0x92 を読んでホスト側で
  オフセット保持）。フラッシュ摩耗ゼロ・再起動不要で、日常のゼロ合わせはこちらを推奨。
- ROM 書き込み系（0x32/0x43/0x63/0x64）はフラッシュ書換え寿命があるため、キャリブレーション
  等の低頻度操作に限定すること。
- 0xB6 アクティブリプライを有効にすると該当コマンドへの通常応答が返らなくなる点に注意
  （現行ドライバの transact はエコー応答前提のため、併用不可）。
- X-series User Manual（電気・機械仕様書、プロトコル詳細は含まない）からの補足: CAN終端は
  両端に 120Ω 必須、モデルにより電圧クラス(24/48/72V)・電流/トルク定格・エンコーダ分解能
  (17/18bit)が大きく異なる（`RunMode`/ゲイン値等のスケーリングをモデル間で使い回さないこと）。
  また「過電圧/低電圧保護しきい値」という設定可能パラメータの存在が示唆されているが、
  対応する CAN コマンドバイトは3マニュアルいずれにも見当たらず、未解決の手がかりとして残す。
