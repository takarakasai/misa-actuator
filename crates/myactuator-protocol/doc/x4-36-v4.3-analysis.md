# X4-36 (RMD-X4-P36-36) 公式マニュアル 突き合わせ結果

出典（2026-07-26 取得、英語版、いずれも MYACTUATOR＝蘇州密控節能科技/Suzhou Micro Actuator
Technology Co., Ltd. 公式配布、`aifitlab.com` 製品ページ経由 → `cdn.shopify.com` 直リンク）:

- `ref/X4-36_Motor_Motion_Protocol.pdf` — "Servo Motor Control Protocol", **Version V4.3**,
  Date 2025.05, Applicable driver: V3。既存の `RMD-X-Servo-Motor-Control-Protocol-V3.91.pdf`
  の後継バージョン（V3.91 → V4.3）。全 101 ページ。
- `ref/X_Series_User_Manual_en.pdf` — "Instruction Manual for the Product", Applicable series:
  X series, Version V1.1, Date 2025.05。X4-36 を含む X シリーズ全体のハードウェア仕様書。

読みやすい形に整形した全文は `x4-36_motor_motion_protocol_en.md` /
`x_series_user_manual_en.md` を参照。本ドキュメントは `myactuator-protocol` /
`myactuator-driver` の実装との差分・X4-36 固有パラメータだけをまとめる。

## 結論サマリ

1. **重大なバグを発見・修正済み**: モーションモード (`0x400+ID`→`0x500+ID`) の応答フレーム
   デコードが1バイトずれていた。実機 (X4-36, 2026-07-26 hw_check) で観測された
   「pos/vel/tau が指令を変えても固定値のまま」という不具合の根本原因が、公式マニュアル
   §5.3 の応答フレーム定義と突き合わせることで判明。**修正済み**（`motion.rs`）。
2. V3.91 → V4.3 のバージョン差は、本 crate が実装している範囲（0x140/0x240 単体コマンド、
   0x400/0x500 モーションモード）では**実質差分なし**。MIT レンジ (±12.5 rad / ±45 rad/s /
   kp 0–500 / kd 0–5 / ±24 N·m) も完全一致。
3. X4-36 固有のハードウェアパラメータ（Kt, 減速比, 定格/最大トルク等）を確認。ドライバは
   `MotorConfig::new(kt)` で Kt を外から渡す設計なので、X4-36 を使う場合は
   `MotorConfig::new(1.9)` を指定するのが正しい（現状 `hw_check.sh` はデフォルト `--kt 0`
   ＝カレント単位のまま運用されている）。

## 1. 【重要】モーションモード応答デコードのバグを特定・修正

### 症状（2026-07-26 hw_check ログより）

```
mit: motor=  1 pos=-11.865 rad  vel=-35.703 rad/s  tau=+23.906 Nm  iq=+23.91 A  T=0 °C
```
（kp=5, kd=0.5 で hold している間、複数サンプルにわたり **完全に同一の値** が返り続けた。
速度が非ゼロなのに位置が変化しない、というのは物理的にありえない。）

### 根本原因

V4.3 マニュアル §5.2/§5.3 を確認すると、**コマンド側とリプライ側でバイトレイアウトが違う**:

| byte | コマンド (`0x400+ID`, §5.2) | リプライ (`0x500+ID`, §5.3) |
|---|---|---|
| DATA[0] | p_des 上位8bit | **応答元モータの CAN アドレス**（コマンドバイトのエコーではない） |
| DATA[1] | p_des 下位8bit | p_des 上位8bit |
| DATA[2] | v_des 上位8bit | p_des 下位8bit |
| DATA[3] | v_des下位4bit / kp上位4bit | v_des 上位8bit |
| DATA[4] | kp 下位8bit | v_des下位4bit / t_ff上位4bit |
| DATA[5] | kd 上位8bit | t_ff 下位8bit |
| DATA[6] | kd下位4bit / t_ff上位4bit | NULL |
| DATA[7] | t_ff 下位8bit | NULL |

修正前の `parse_motion_reply` はコマンド側と同じレイアウト（`data[0]` が p_des の上位バイト）
だと仮定していたため、実際には CAN アドレス（例: モータID=1 なら固定で `0x01`）である
`data[0]` を位置データの一部として誤読していた。これにより、実際の位置がどう変化しても
デコード結果はほぼ固定値に張り付く（"stuck" 症状）。

マニュアル §5.4 の応答ワークアウト例（ID `0x501`, ペイロード `01 E6 66 82 EB 55 00 00`）で
再検算し、修正後のオフセットで手計算値（pos≈10.00 rad, vel≈1.021 rad/s, t_ff≈10.004 N·m）と
一致することを確認済み。テスト `reply_parses_manual_worked_example` として追加。

### 修正内容

`crates/myactuator-protocol/src/motion.rs::parse_motion_reply`:

```rust
// 修正前（誤り）: data[0] を p_des の上位バイトとして読んでいた
let p = ((data[0] as u16) << 8) | data[1] as u16;
let v = ((data[2] as u16) << 4) | (data[3] >> 4) as u16;
let t = (((data[3] & 0xF) as u16) << 8) | data[4] as u16;

// 修正後: data[0] は CAN アドレスなのでスキップし、p_des は data[1..3] から
let p = ((data[1] as u16) << 8) | data[2] as u16;
let v = ((data[3] as u16) << 4) | (data[4] >> 4) as u16;
let t = (((data[4] & 0xF) as u16) << 8) | data[5] as u16;
```

`cargo test -p myactuator-protocol` は全16件パス（修正済み）。**次回の実機テストで
`mit` コマンドの pos/vel/tau が実際の動きを追従することを再確認してください**
（`scripts/hw_check.sh --motion` の「motion-mode MIT hold」ステップ）。

## 2. V3.91 → V4.3 バージョン差分（実装範囲内）

| 項目 | V3.91（既存 ref） | V4.3（今回追加） | 差分 |
|---|---|---|---|
| 単体コマンド ID | `0x140+ID` / `0x240+ID` | 同じ | なし |
| モーションモード ID | `0x400+ID` / `0x500+ID` | 同じ | なし |
| MIT レンジ | pos±12.5 / vel±45 / kp0–500 / kd0–5 / t_ff±24 | 同じ | なし |
| Status2 (`0x9C`) 単位 | temp 1℃, iq 0.01A, speed 1dps, angle 1°(int16) | 同じ | なし |
| `0x64`（現在位置→ROM ゼロ） | あり | あり（同一フォーマット） | なし |
| RS485 対応 | 記載あり | 記載あり（ボーレート選択肢が 2.5Mbps まで拡張） | 未実装範囲（本 crate は CAN のみ） |

→ 本 crate が対応しているコマンド部分に関しては、V4.3 で仕様変更は入っていない。今回の
バグはバージョン差ではなく、実装側の初期解釈ミスだったことが確認できた。

## 3. X4-36（RMD-X4-P36-36）固有パラメータ

`X_Series_User_Manual_en.pdf` Table 3-3（Module Parameter list）より、X4-P36 列:

| パラメータ | 値 |
|---|---|
| 減速比 (Ratio) | **36** |
| 定格電圧 | 24 V |
| 最大出力軸速度 | 111 RPM |
| 無負荷電流 | 0.9 A |
| 定格速度 | 83 RPM |
| **定格トルク** | **10.5 N·m** |
| 定格出力 | 100 W |
| 定格電流 | 6.1 Arms |
| **最大トルク** | **34 N·m** |
| 最大電流 | 21.5 Arms |
| 効率 | 63.1 % |
| EMF 定数 | 6.0 Vdc/Krpm |
| **トルク定数 Kt** | **1.9 N·m/A** |
| 相抵抗 / 相インダクタンス | 0.35 Ω / 0.17 mH |
| 極対数 | 13 |
| バックラッシュ | 10 arcmin |

型番 `RMD-X4-P36-36-C` の内訳: `X4` = ベース番号, `P36` = 減速比(丸め値), `36` = 最大トルク
[N·m], `C` = CANBUS 通信（`-E` は EtherCAT）。

**ドライバへの反映:** `myactuator-driver::MotorConfig` は Kt を型に持たせず
`MotorConfig::new(kt)` で都度渡す設計（per-model のハードコードテーブルは無い）。X4-36 を
使う場合は呼び出し側で `MotorConfig::new(1.9)` を指定すること。現状 `scripts/hw_check.sh`
は `--kt` 未指定時デフォルト `0`（= `MotorConfig::current_units()`, Kt=1）で動いており、
その場合 `torque_nm` フィールドの実体は生の A 表示になる（意図した運用であれば問題ないが、
Nm 表示が欲しい場合は `--kt 1.9` を渡す必要がある）。

## 4. 未確認・要フォローアップ

- RS485 経由の X4-36 制御（CRC16 フレーム）は `myactuator-protocol` 未対応。CAN のみで
  運用している限り影響なし。
- `0x30`〜`0x32`（PID読み書き）、`0x42`/`0x43`（加速度）、`0xB3`/`0xB4`（タイムアウト/
  ボーレート）は既存の `doc/data-map.md` の通り未実装のまま（今回のバージョンアップでも
  仕様変更なし、着手する場合は V4.3 マニュアルの該当セクションを参照）。
- モーションモード応答の修正は section 5.4 のワークアウト例 1 件のみで検証。実機での
  再テストを推奨（上記§1参照）。
