## 1. DM-J4310-2EC

### 1.1 同定済みモータ定数(レジスタ読み出し)

| 量 | 値 |
|---|---|
| 極対数 `NPP` | 14 |
| 磁束 `Flux` | 0.00449164 Wb |
| 減速比 `Gr` | 10 |
| ギア効率 `GREF` | 1.0 |
| 相抵抗 `Rs` | 0.72551 Ω |
| 相インダクタンス `Ls` | 330.59 μH |
| 粘性 `Damp` | 5.2233e-4 |
| ロータ慣性 `Inertia` | 1.7915e-5 |

**トルク定数**はマニュアルの式 `Kt = 1.5 * Npp * ψf * GR * GREF` から算出:

```
Kt = 1.5 * 14 * 0.00449164 * 10 * 1 = 0.94324 N·m/A   (出力軸換算)
```

裏付け2点:

- `Imax` (10.2612 A) × Kt = **9.68 N·m** に対し `TMAX` = 10 → 駆動電流上限がトルクマッピング範囲にほぼ一致
- 実機の `Flux` がマニュアル記載例 `Ψf = 0.0045 Wb` と一致

`KT_Value` レジスタは **0**。これはマニュアルどおり「同定済みパラメータを使う」正常状態
(未校正ではない)。

| | 実測(レジスタ) | SDK の `Limit_Param` |
|---|---|---|
| `PMAX` | 12.5 | 12.5 |
| `VMAX` | 30 | 30 |
| `TMAX` | 10 | 10 |

SDK 4コピーが一致していた DM4310 エントリと**完全一致**。既定値と `LimitsSource::Sdk`

### 1.3 制御ループゲイン・保護しきい値

| 速度ループ | `KP_ASR` 0.0045301, `KI_ASR` 0.015708, `Deta` 4, `V_BW` 50, `VL_c1` 200 |
| 位置ループ | `KP_APR` 54, `KI_APR` 0 |

### 1.4 MIT スケーリングの定量検証

`kp = 5` で3点測定。**`τ = kp × 偏差` が全点で成立**。

| 指令位置 | 実位置 | 偏差 | 理論トルク | 実測トルク | 誤差 |
|---|---|---|---|---|---|
| +0.151 rad | +0.063 | +0.088 | +0.44 N·m | **+0.418** | -5% |
| −0.049 rad | −0.009 | −0.040 | −0.20 N·m | **−0.208** | +4% |
| +0.300 rad | +0.090 | +0.210 | +1.05 N·m | **+1.013** | -4% |

量子化チェーン全体(位置 `PMAX` 16bit / kp 12bit / トルク `TMAX` 12bit)が正しい。

### 1.5 3制御モードの動作

| モード | 指令 | 実測 |
|---|---|---|
| MIT (`CTRL_MODE`=1) | 上記 | τ = kp×偏差 |
| Position-Velocity (=2) | 0.27 rad | **0.271 rad**(誤差 0.001) |
| Velocity (=3) | 0.2 rad/s | 0.125〜0.168 rad/s |

### 1.6 リグの負荷特性

**独立した2手法が一致**した。

| 手法 | 静的負荷 | 摩擦 |
|---|---|---|
| `load-map`(往復ヒステリシス対、±0.12 rad) | 0.068 N·m | 0.126 N·m |
| `breakaway`(両方向差分、+0.1842 / −0.1661) | **0.009 N·m** | **0.175 N·m** |

`breakaway` 側が大きいのは静止摩擦 > 動摩擦という教科書どおりの関係。
つまり釣り合い点近傍は**ばね/重力負荷がほぼ無く摩擦支配**。

**+0.14 rad 付近から急に硬くなる**(機構の噛み合い):

| 釣り合い点からの変位 | 保持トルク |
|---|---|
| ±0.04 rad 以内 | 0.17 N·m 程度(摩擦プラトー) |
| +0.138 rad | 0.945 N·m |
| +0.201 rad | 6.7 N·m |

### 1.7 熱特性

出力軸が機構で拘束されていたため**唯一測定が成立した**ケース。

| 項目 | 値 |
|---|---|
| 指令トルク | 1.5 N·m |
| 実効トルク | **1.218 N·m**(delivered 81%) |
| 温度上昇率 | **+0.116 ℃/s** |
| 55 ℃ 到達 | **225 秒** |

手作業観測(6.7 N·m で約1.7 ℃/s)と τ² スケールで整合。

### 1.8 安全面の重要な挙動

**`disable` は保持される安全状態ではない。** `disable` 直後に `mit --kp 5` を送ると
**1.013 N·m を出力**した。次の制御フレームで再励磁される。`status` も内部でゼロゲイン
MIT フレームを送るため `err=Enabled` を再表示する。投入時から励磁状態でもあった。

| 速度ループ | `spd_kp` 6, `spd_ki` 0.02, `spd_filt_gain` 0.05 |

| プロファイル | `acc_rad` 20, `vel_max` 10, `acc_set` 10 |

### 2.2 トルク定数 — 独立実測に成功

**4ベンダー中で唯一、循環でない Kt 実測が得られた。**

| | RS04 | DM-J4310 |
|---|---|---|
| Kt 最小二乗 | **1.5093 N·m/A** | 0.9432 |
| Kt 点ごと平均 | **1.4847 N·m/A** | 0.9432(完全一致) |
| フィット R² | **0.9980** | 1.0000(完全) |

**2つの推定値が食い違い R² が 1 未満であることが独立性の証拠。** RS04 はトルクを MIT
フィードバックフレームから、電流を別の `IqFilt` パラメータ読み出しから得ている。
DM-J4310 は電流をトルク÷Kt で導出しているため代数的に自明で、物理を検証していない。

参考の整合性: `limit_torque` 115 / `limit_cur` 97 = 1.185 N·m/A(同オーダー。ただし
両者は独立した保護上限であり Kt そのものではない)。

### 2.3 リグの負荷特性

| 手法 | 結果 |
|---|---|
| `breakaway`(両方向 +0.0135 / −0.0948) | 静的負荷 −0.041、摩擦 0.054 ← **⚠ 単位がアンペア、かつジャダー誤検出。§7 で 0.902 N·m に訂正** |
| `load-map` | 全点トルク **0.0000** |

**⚠ 当初「摩擦がトルク分解能以下」と説明したが誤り。** 分解能は RS04 が 3.66 mN·m/LSB
(16bit / ±120 N·m)で DM-J4310 の 4.88 mN·m より細かい。真の原因は
**Position/Torque モードのフィードバックが `measure_safe`(パラメータ読み)経由で、
この機体の `MeasuredTorque`(0x302C) が常に 0 を返すこと**だった(3 run 72サンプルで
非ゼロ 0 件、MIT 経路では 109/109 が非ゼロ)。`IqFilt` は Position モードでも動くので
`--kt` で `torque = current × Kt` として復元できる。

ただし復元後も RS04 の `load-map` は成立しなかった。**位置ループがハンチング**するため
(ドウェル内振幅 0.998 N·m がピーク保持トルク 0.747 N·m を上回る)。摩擦 0.9 N·m に対し
`loc_kp`=80 では減衰が足りない。→ §7 のトルク制御/速度制御による測定に移行。

### 2.4 位置制御精度(目視確認済み)

±0.6 rad(合計 **68.8°**)を 17.2° ずつ5段階で往復。

| 点数 | 目標との誤差 |
|---|---|
| 13点(±0.3 rad 掃引) | **±0.0004 rad = ±0.02° 以内** |
| 9点(±0.6 rad 掃引) | 同等 |

到達待ち(`arrive_tolerance_rad`)が機能していることを目視と数値の両方で確認。

### 2.5 熱特性 — 測定不成立

自由軸のため**測定できない**。leash が保持トルクを打ち消す(§3参照)。

| 指令 | 実効 | 判定 |
|---|---|---|
| 2.0 N·m | 0.141〜0.251 N·m (delivered 13%) | 測定不成立として報告 |

### 2.6 フィードバックの取得可否

| 量 | 状況 |
|---|---|
| 位置・速度・トルク | フィードバックフレームに含まれる |
| **電流** | **フレームに無し。** `--report-current` で `IqFilt`(0x701A) を追加読み出し(往復1回増) |
| **温度** | **`mit_control` 経路のみ。** `measure_safe` はパラメータ読みで組み立てるため NaN |

### 2.7 パラメータテーブルがファームウェアと不一致(危険)

ファームウェアが自己申告する84行のうち **32行**がマニュアル由来の静的テーブルと不一致。
`0x2006`–`0x2021` と `0x3010`–`0x301C` が1〜4行シフト。生バイトが正否を決めた:

| FunctionCode | 生バイト | 実際 | テーブルの主張 |
|---|---|---|---|
| `0x2009` | `[01 FD 00 00]` → 1 = addressing 中の CAN ID | **CAN_ID** | `motor_baud` |
| `0x200A` | `[FD 00 00 00]` → 253 = 指定した host-id | **CAN_MASTER** | `CAN_ID` |

テーブルを信じて `motor_baud` にボーレート値を書くと **CAN ID を上書き**しバスから消える
(SET_CAN_ID インシデントと同じ失敗様式)。詳細は
`crates/robstride-protocol/doc/param-table-firmware-divergence.md`。

## 4. 熱試験には出力軸の機械的拘束が必須

固定トルクの熱試験は**出力軸が拘束されていないと成立しない**。leash(位置保持)は
暴走を防ぐが、定常状態では軸が `err = -tau_ff / kp` に落ち着き、モータの発生トルクは
`kp * err + tau_ff = 0` と**打ち消される**。

DM-J4310 で測定できたのは、あのリグの負荷(§1.6の硬化領域)が実質的な拘束として
働いていたため。RS04 は摩擦 0.054 N·m しかなく自由に打ち消し点まで動けるので不成立。

`Thermal::delivered_fraction()` が指令の何割が実際に出たかを報告し、50%未満では
時間換算を拒否する。

## 7. 追加解析: 「動摩擦 >> 静止摩擦」の異常を解決

`velocity-sweep` を実装した直後、RS04 で **動摩擦 0.584 が静止摩擦 0.054 の約9倍**という、
通常の順序(静止 > 動)と逆の結果が出た。原因は**2つのバグが重なっていた**ことだった。

### 7.1 切り分けの経過

| 仮説 | 検証方法 | 結果 |
|---|---|---|
| 位置ハンチングの混入 | 速度の統計を見る | **速度sd/平均=0.62、往路中に負へ反転** → スティックスリップ確認 |
| 定常でない区間の混入 | 速度が指令±25%の区間だけ抽出 | 0.614 と**改善せず** |
| 加速中の混入 | 加速度<中央値20%も追加 | 0.580 と**改善せず** |
| 変位しきい値による早期トリガ | 速度のみでトリガ | 0.038 と**変化なし** |
| **速度依存(粘性)** | 0.08 / 0.4 / 1.0 rad/s で掃引 | **0.584 / 0.531 / 0.530 → 速度非依存** |
| **指令電流が流れていない** | ランプ中の実測電流を記録 | **指令 0.1177 に対し実測 0.1178 → 一致** |

速度を12倍にしてもスティックスリップがほぼ消えても動摩擦が変わらないため、
**振動由来のアーティファクトではなく実在する約0.53 N·mのクーロン摩擦**と確定した。

### 7.2 原因1: `Actuator::set_torque` が N·m ではなくアンペアを指令していた

RobStride のトルクモードのパラメータは `IqRef` = **q軸電流**であり、ドライバは
トレイトの N·m をそのまま書き込んでいた。実測電流が指令と 0.0001 A で一致することを
確認済みなので、これは純粋に単位の取り違えである。

**`breakaway` の報告値は Kt 倍だけ小さく出ていた**(RS04 では 1.5093 倍、つまり
要求したトルクの約2/3が欠けていた)。`Kt` が既知なら `IqRef = τ / Kt` に変換するよう修正。

### 7.3 原因2: `breakaway` がジャダーのスパイクでトリガしていた

ランプ中の生ログで、指令がまだ 0.12 A の時点で**速度が ±0.08 rad/s を正負両方向に
何度も往復**していた。真に破断していれば加速していくはずで、これは軸が微小に
前後する「判り」であり、速度しきい値の単発クロスを破断と誤認していた。

`motion_hold_s`(既定 0.1 s)を追加し、**しきい値超えが継続しない限り破断とみなさない**
ようにした。記録するトルクは「動き出した時点」の値なので、ホールド時間で値が水増し
されることはない。

### 7.4 修正後の結果

| 段階 | 静止摩擦 |
|---|---|
| 修正前 | 0.054（単位はアンペア） |
| 単位換算のみ | 0.082 N·m |
| **持続動作要求も追加** | **0.902 N·m** |

| | 静止摩擦 | 動摩擦 | 比 |
|---|---|---|---|
| **RS04** | **0.902 N·m** | **0.530 N·m** | **1.70** |
| DM-J4310 | 0.175 N·m | 0.126 N·m | 1.39 |

**静止摩擦 > 動摩擦の正しい順序**になり、比も両機で 1.4〜1.7 と物理的に妥当な範囲に
収まった。

### 7.5 教訓

- **DM-J4310 では両バグが顕在化しなかった。** 摩擦が 0.175 N·m と大きく破断が明瞭で
  ジャダーせず、かつ MIT モード(N·m スケール済み)経由で測っていたため単位問題も出なかった。
  **1機種だけの検証では両方とも見逃していた。**
- 速度を変えて測る(粘性か否かの切り分け)、指令と実測を突き合わせる(単位・追従の検証)、
  この2つが原因特定の決め手になった。

### 7.6 未解決

- **RS04 の摩擦 0.53〜0.90 N·m は §2.3 の 0.054 と大きく異なる。** 後者は単位がアンペアで
  かつジャダー検出だったため。**本文書の §2.3 の数値は修正前のものであり信頼できない。**
  正しい値は本節の 0.902 N·m(静止)/0.530 N·m(動)。
- `motion_hold_s` はランプ時間(`ceiling / ramp`)より十分短くする必要がある。長すぎると
  上限到達が先に来て破断が確定しない(既存テストで実際に発生した)。
